# GGA1C.Sync — цель и состояние

Не история, а цель и текущее состояние. Обновлено 2026-10-28.

## 1. Цель

**GGA1C.Sync** — интеграционный хаб на Windows Server рядом с Altium on-prem, SOLIDWORKS PDM и
1С. Он связывает системы, которые сами друг с другом не разговаривают, и делает это **от имени
конкретного человека**, а не одной общей учётки.

Модули, в порядке работы:

1. **Печать** этикеток (PDF) и наклеек (.ezpx): шаблоны, привязанные к изделиям из Grist,
   редакторы шаблонов, прямая печать наклеек на принтеры по сети.
2. **SolidWorks / PDM**: add-in SolidWorks, задача смены ревизии с генерацией чертежа,
   передача чертежей в Grist. Описание модуля неполное.
3. **Altium ↔ 1С**: компоненты в обе стороны, спецификации, остатки складов внутри Altium.

Люди работают в привычных программах: конструктор — в Grist и Altium, оператор — у принтера.
**Хаб видят те, кто создаёт и правит шаблоны** (страница открывается из виджета Grist), и
администратор: учётные записи, подключения, журналы, настройки.

Обязательное условие во всех модулях — разделение по людям: каждое действие выполняется от
имени того, кто нажал, и пишется в журнал; отключили человека в Keycloak — закрылся и доступ.

## 2. Что работает сейчас по-настоящему

- **Хаб**: ABP 10.7 + Blazor Server + MudBlazor, EF Core 10, MySQL 8.4 (одна база `gga1c`).
- **Поток Grist → хаб**: виджет Grist (v0.53.0) шлёт партию этикеток, хаб опознаёт человека по
  **токену Keycloak** (подпись по JWKS, издатель, срок, клиент) и пишет строки с его меткой.
  Проверено живыми людьми: каждый попадает в свой буфер.
- **Учётки людей** приходят из Keycloak (связь по `sub`), сверка раз в час; отключение в
  Keycloak отключает и печать.
- **Печать через GoLabel**: GoLabel II подключается к MySQL логином-почтой человека и читает
  представление `my_labels` — только свои строки (прав на таблицу нет, проверено `ERROR 1142`).
  Учётка MySQL создаётся автоматически; пароль виден и меняется в карточке человека.
- **Лишние подключения GoLabel** закрываются в момент нового входа (`init_connect` + процедура).
- **Выгрузка CSV** на человека (`C:\GGA1C\labels\<папка>\labels.csv`) — равноправный источник.
- **Веб-интерфейс**: «Grist → GoLabel2» (`/labels`), «Keycloak» (`/keycloak`),
  «Altium → 1С» (`/altium-1c`), карточка учётных данных человека (Altium / PDM / печать).
- **Секреты** шифруются и наружу не отдаются (маска длины); исключение — пароль печати.

## 4. Чем заняты сейчас

Модуль печати. Первая задача — баг с окном входа Keycloak при синхронизации из виджета, затем
инструменты сравнения печати (фейк-принтер) и перенос ядра GoLabel. План — `docs/roadmap.md`.

## 5. Принятые решения

- **Порядок модулей**: печать → SolidWorks/PDM → Altium ↔ 1С.
- **Одна база MySQL 8.4** — GoLabel умеет MySQL своим драйвером, SQLite не читает вовсе.
- **MariaDB отвергнута** — провайдер, который тянет ABP, падает на ней; Pomelo под EF Core 10 нет.
- **Личность человека даёт Keycloak**, проверяет хаб — в документе Grist ни ключей, ни таблиц.
- **Разделение в печати через GoLabel держит СУБД** (представление + права).
- **Печать наклеек — из хаба напрямую на принтер** по Ethernet (TCP 9100), от имени нажавшего
  в виджете. GoLabel остаётся вторым путём на переходный период. (Прежнее решение «редактор
  этикеток в вебе не делаем» отменено.)
- **Ядро печати — порт декомпилированного `QLabelSDK` GoLabel II.** Запасной путь, если порт
  окажется нерабочим, — печать самим GoLabel из командной строки на сервере; `Trace.dll` —
  инструмент отладки транспорта. Подробности — `docs/printing/decisions.md`.
- **Регистрация — как в Docmost**: при первом развёртывании, пока нет администратора, открыта
  форма создания администратора (пароль дважды); дальше самостоятельной регистрации нет.
- **Дерево изделий ведёт Grist**; хаб хранит только шаблоны и id из Grist.
- **Логин печати = почта человека** (если почты нет или она длиннее 32 знаков — `lbl_<папка>`);
  создаётся автоматически.
- **Секреты наружу не отдаются** (маска длины), кроме пароля печати — его диктуют оператору.
- **В репозитории только сервис**; виджет правит отдельный чат.
- **Elsa** — место оставлено, встраивание по необходимости модулей.
- **Настройки боевого Keycloak не меняются.** Стенд правим как угодно, но решение не может
  опираться на правку боевого реалма (время сессий, клиенты).
- **Файлы в базе хаба не храним** — только ссылку. Сами файлы — на NAS через FastAPI-сервис.

## 6. Открытые вопросы

- **Keycloak будет федерован с AD?** От этого зависят права на папки CSV по доменным учёткам.
- **Операторы входят в Windows личными учётками или общей?** Если общей — CSV по папкам не
  разделяет людей, остаётся только MySQL.
- **PDM не умеет SAML/OIDC** — как действовать от имени человека: служебная учётка с
  атрибуцией, агент на рабочем месте или хранение личных паролей. Блокирует модуль 2.
- **Altium**: пагинация компонентов (программная сессия получает первые 50, с куками браузера
  работает). Блокирует модуль 3. Отдельно пользователь называет неработающие лицензионные ключи
  Windchill — это **пересмотр тупика** из §7 с новой причиной, детали не собраны.
- **Авторизация в бою (вместе с TLS).** Боевой Grist `db.mp-lab.ru` стоит за FastAPI-шлюзом с
  входом через Keycloak (realm `master`, `fastapi-client`) — шлюз знает вошедшего и сам держит
  его сессию. Варианты: (А) виджет, отдаваемый с того же адреса, спрашивает у шлюза «кто я /
  текущий токен» и передаёт токен хабу; (Б) хаб за шлюзом (`db.mp-lab.ru/sync/...`) — заодно
  уходит mixed content. Хаб в обоих случаях сам проверяет подпись токена. Ждёт ответа: можем ли
  менять код шлюза. Прочие варианты TLS: внутренний УЦ с раздачей сертификата политиками,
  отказ от вызовов из браузера.
- **Встраивание страницы шаблонов в виджет** — после отдельной страницы; вход внутри фрейма
  только по токену, не по куке.
- **Повтор печати** — нужен ли.

## 7. Отказались

- **SQLite-буфер + ODBC-DSN на рабочих местах** — в GoLabel II нет ODBC вообще.
- **Файл-буфер на человека** — довод «в SQLite нет пользователей» исчез вместе со SQLite.
- **Ключи учёток в таблице Grist** — открытым текстом, видны владельцу, уезжают в выгрузки.
- **Таблица почт в Grist + токен Grist** — требует от хаба прав на запись в документ.
- **Почта или ключ в настройках виджета** — настройки секции общие на документ.
- **Ключ в `localStorage`** — привязка к браузеру, а не к человеку.
- **Опознание через сессию Grist** (хаб за nginx Grist, запрос несёт куку, хаб спрашивает
  `/api/session/access/active`) — заменено токеном Keycloak.
- **`MAX_USER_CONNECTIONS = 1`** — сервер отказывает новому соединению, ломает обновление.
- **Готовые iPaaS (n8n, Kestra, NiFi)** — коннектор к PDM это COM, он обязан жить в C#-процессе
  на Windows; вторая система только добавила бы HTTP-прослойку и ресурсы (n8n в простое —
  300–500 МБ плюс Postgres против 116 МБ всего прежнего сервиса).
- **Пересборка `Trace.dll`/`EZio32.dll` в x64** — нативный код без исходников; x86-посредник.
- **Перенос `Neodynamic.SDK.Barcode.dll`** — работает на лицензионном ключе GoDEX; ZXing.Net.
- **PLM Integration через Windchill / Teamcenter EDA (фейковый шлюз)** — AES требует
  установленный клиент Siemens и лицензию; синхронизация идёт через `/components/api/...`.
