# Модуль 3 — Altium ↔ 1С

**Первая версия не заработала.** Модуль начинать с разведки блокеров, а не с кода.

## Функции

**F1. Компоненты в обе стороны.** Компонент создан в Altium → ищем такой же **по всей
номенклатуре 1С** (не только в целевой папке — компонент мог лечь не туда, дубли недопустимы).
Нашли — возвращаем код 1С в компонент Altium. Не нашли — создаём в 1С в категории по правилам
конструктора структуры (модуль, где структуру можно поправить вручную: добавить/удалить папки и
подпапки) и возвращаем код в Altium. **Новых папок F1 не создаёт.**

**F2. Спецификации.** Из проекта берём: печатную плату и смонтированную плату (обозначение и
наименование обеих), корневой проект (в свойствах проекта), BOM (компоненты, количество, код 1С).
Конструктор раскладки определяет, что куда идёт. В 1С создаётся папка **«<корневой проект>»**
(например, «ГКВ-120»), в ней **«1.на монтаж»**, туда кладётся спецификация.

**F3. Остатки складов 1С внутри Altium** через ActiveBOM — нужен провайдер компонентов или
перемычка. Сначала разведка, как устроен механизм провайдера.

Всё — от имени человека (учётка Altium в карточке), с записью в журнал.

## Обнаруженный API Altium (реверс через DevTools, НЕ документирован)

- `GET /components/api/tags` — дерево тегов/папок: `{tags:[{guid,name,parentGuid,subTags,count}], totalCount}`
- `GET /components/api/components?fields[]=Id&fields[]=Comment&...&text=&tag={guid}&orderby=&start=0&limit=50`
  — компоненты, жёсткий лимит 50 на страницу; параметры скопированы из реального запроса браузера.
- Компонент: `Id (R_...)`, `ItemGUID`, `Comment` (артикул), `Description`, `Manufacturer`,
  `FootprintName1` и кастомные поля `Наименование 1С`, `Наименование`, `Код`.
- Авторизация: form-login `POST /Account/Login` → cookie `.AFSAUTH` + `ASP.NET_SessionId`.

## Пагинация — нерешённая

**Симптом:** программные запросы с `tag=` и `start=` всегда возвращают первые 50 компонентов,
игнорируя оба параметра — даже для тега с 3 компонентами (Audio).

**Диагностика:**
- С куками браузера (скопированными из DevTools) те же запросы работают (Audio → 3).
  Значит, дело не в URL, а в серверном сессионном контексте.
- Кука `A365_LIBRARYCOMPONENTSAPI_DOWLOAD_SESSION` создаётся браузером (видимо, JS SPA при первой
  загрузке `/components`), не обычным `Set-Cookie`.
- Warmup-запросы к `/librarycomponentsapi/api/v1/...` куку не создают. Ручная установка куки со
  случайным GUID не помогла (финальный статус не подтверждён — перепроверить).

**Временный обход (в коде хаба):** поле «Куки браузера» — настройка
`SyncSettings.Altium.BrowserCookies` (секрет). Пользователь копирует заголовок Cookie из DevTools
раз в ~24 ч; `AltiumService` при заданном поле шлёт запросы с этими куками.

**Следующий шаг:** DevTools → Network → hard refresh `/components` с нуля → первые 10–15 XHR до
загрузки списка; один из них инициализирует контекст. Особое внимание — `/librarycomponentsapi/...`.

## Тупиковые ветки — не переоткрывать без причины

1. **PLM Integration через Windchill** — в AES 7.2.6.5 в списке драйверов только «Teamcenter EDA»,
   Windchill пропал (был в 6.0.5.28); лицензии Windchill PLM Addon не нашли.
2. **PLM Integration через Teamcenter EDA (фейковый шлюз)** — эмулятор EDA Gateway работал по
   сети, но AES требует **локально установленный** EDA Gateway Client Siemens и лицензию
   Teamcenter PLM Addon («EDA Client location is not set») — сетью не решается. Код
   (`EdaGatewayController`, `/tc/...`) — в истории прежнего эскиза, в хаб не переносился.
3. **OAuth2-провайдер** (`/oauth/authorize`, `/oauth/token`) — делался под Windchill, не
   пригодился; тоже только в истории эскиза.

Синхронизация идёт напрямую через `/components/api/...`.
