## 1. Печать из командной строки — есть

`CmdlineHelp.txt` и разбор аргументов (`GoLabel\QLabelNet\Program.cs`, `CommandMode`):

```
GoLabel.exe -f "<копия>.ezpx" -i 127.0.0.1:9100 [-c копий] [-p страниц]
            [-V00 значение ...] [-S0 100 ...] [-db "<файл>.csv"] [-r 1-3]
            [-dark 0..19] [-speed ips] [-stop n] [-pmode 0|1] [-option N|S|A] [-cut n]
GoLabel.exe -view "<файл>.ezpx" -save "<файл>.bmp" [-zoom 0.1..2]   # картинка-превью
```

- `-i A.B.C.D[:порт]` переключает задание на `CommunicationType.Network` с этим адресом; без
  порта — 9100. Любой порт годится, значит фейк-принтер можно держать и не на 9100.
- **Без `-i` печать идёт туда, что записано в самом `.ezpx`** (в файле есть
  `CommunicationType`, `NetworkIPAddress`, `NetworkPort`, `DriverName`) — может уйти на
  настоящий принтер. Поэтому `-i 127.0.0.1:<порт>` — обязательно в каждом вызове.
- Командный режим разбирается **до** проверки «GoLabel уже запущен» (мьютекс) — второй процесс
  с `-f` работает рядом с открытым у пользователя GoLabel, не трогая его окно (по коду; живьём
  не проверено).
- **GoLabel перезаписывает `.ezpx` после печати**: при `langsetSaveSerial=True` (так у
  пользователя в `user.config`) вызывается `drawArea.SaveToXml(<файл>)` — в шаблон сохранятся
  сдвинутые счётчики и подставленный `-i`. Печатать **только с копии** шаблона.
- Шаблон, привязанный к базе: командная строка подключает только OleDb-источники и
  `-db` (txt, csv, xls, xlsx). Шаблоны, читающие MySQL `my_labels`, для эталона печатаем с
  фиксированным CSV через `-db` (или `-V`), иначе данные не воспроизводимы. Как поведёт себя
  шаблон с MySQL-источником без `-db` — не проверено.

## 4. Сокет или спулер

Транспорт выбирает `QLabelSDK.PrinterControl.Printer` по `CommunicationType`:

| Тип | Как уходят байты |
|---|---|
| `Network` | **управляемый .NET-сокет** `SocketSDK` (TCP на IP:порт, байты как есть, без перекодировки) — **не `Trace.dll`** |
| `USB`, `COM`, `LPT` | `Trace.dll` (`OpenUSB`/`OpenCom`, `SendBuf`, `RcvBuf`) |
| `Driver` | `winspool.Drv` (`OpenPrinter`, `StartDocPrinter`, `WritePrinter`) |
| `PrintToFile` | в `MemoryStream`, на диск не пишется (так работает `-view`) |

Значит: эталон снимаем сокетом (`-i 127.0.0.1:порт`), порт принтера Windows и спулер не нужны.
`OpenNet` в `Trace.dll` есть (строка в бинарнике), но `QLabelSDK` его **не импортирует** — в
`API_EZio` только `OpenCom/OpenUSB/FindFirstUSB/FindNextUSB/SendBuf/RcvBuf/SetLogPath/EnableLog/...`.
Вывод для П4: при сетевой печати GoLabel `Trace.dll` не участвует; TraceHost через `OpenNet` —
это другой транспорт, и сверка с эталоном проверит только, что он не искажает байты.

**Решение пользователя (2026-10-28):** `Trace.dll` — инструмент отладки транспорта. Запасной
путь, если наш порт окажется нерабочим, — **печать самим GoLabel из командной строки на
сервере** (`GoLabel.exe -f <копия>.ezpx -i <IP принтера>`, как в сценарии съёма эталонов).

## 5. Нужно ли отвечать на статус

По коду — **нет**. Все места, где `QLabelSDK` читает ответ при печати (`PrintJob.ReadStr` в
`CheckReply_FW_Enable` и `QLabel.QueryReplyData`), закрыты флагом `CheckReply`. Чтения ответа
бывают лишь при включённых настройках, которые у пользователя выключены:
`CheckReply` (`^XSET,ACTIVERESPONSE,1` + `~K1`, ждёт ответ), `bUseSyncDateTime` (`~D…`, в
командном режиме вообще не ставится), RFID (`~S,CHECK`, ждёт `00`). Отдельно: если соединение
с 9100 не удалось за 5 с, `SocketSDK` идёт на порт **4900** с текстом `printer state` — только
при сбое, фейку не нужен. **Подтверждено живым прогоном**: на `Sample2` фейк ничего не
отвечал, GoLabel отдал задание одним соединением и завершился.

Минимум для фейка: принимать соединение, читать до закрытия, ничего не слать. Режим ответов —
опция на будущее: на `~S,CHECK` → `00\r\n`, на `^XSET,ACTIVERESPONSE` и `~V` — заготовленные
строки из настоящего принтера (снимать не будем, пока не понадобится).

Что увидим в байтах (вопросы карточки): `^XSET,UNICODE,2/0` обрамляет задание, только если
модель начинается с `EZ` и в задании есть `AT,` — для `ZX430i` по коду не добавляется.
Проверено на настоящих шаблонах — раздел «Что показали байты» ниже.

### Что показали байты

Общее для всех 13: шапка `^XSETCUT,DOUBLECUT,0`, `^Q<длина>,<зазор>`, `^W<ширина>`, `^H`, `^P1`,
`^S`, `^AT`/`^AD`, `^C1`, `^R`, `~Q+0`, `^O0`, `^D0`, `^E`, `~R255`, `^L`, `Dy2-me-dd`, `Th:m:s`,
объекты, `E`. Строки — `CR LF`. Других команд (кроме `ATA`, `Dy…` и `Q`) нет.

- **Шрифты GoLabel не загружает.** Ни в одном задании нет команд загрузки шрифта или картинки в
  память принтера и нет `^XSET,UNICODE`. Текст шрифтом принтера идёт ссылкой на шрифт `A`:
  `ATA,39,0,29,29,0,0BE,A,0,ЛМП` (в шаблоне — `Text`, `GlavkonGOST Type A`, 7 pt, `FontId="A"`;
  29 точек ≈ 7 pt при 300 dpi). Значит, шрифт `A` должен уже лежать в принтере — есть ли он в
  192.168.55.127, не проверено (принтер не трогали). Разбор полей `AT` по П3: `0BE` — поворот 0,
  `B` (жирный), `E` (данные в UTF-8).
- **Русский текст — UTF-8 как есть**, без перекодировки и без обрамления: `ЛМП` = `D0 9B D0 9C
  D0 9F`, `№` = `E2 84 96`. cp1251 нигде нет. Так идёт текст 7 шаблонов с объектами `Text`
  (`gkv1-*`, `gkv3-vm-box`, `gkv3-vm-product`, `gkv3-product`).
- **Текст шрифтом Windows — картинкой.** Объекты `GdiWindowTextBox`/`WindowTextBox` (шаблоны
  91.5×39: `gkv3-box`, `gkv3-vm-box-102x152`, `gkv-avto-*`; шрифты `GlavkonGOST Type A`, `Impact`)
  в байтах — только картинки `Q`, команд текста там нет вовсе. Для побайтового совпадения порту
  нужен тот же растеризатор и те же шрифты в системе (П3); `GlavkonGOST.ttf` на стенде установлен
  в профиль `Administrator`, `impact.ttf` — в `C:\Windows\Fonts`.
- **Штрихкоды (все Code39) — картинкой.** Подпись у них шрифтом Windows (`bBuiltinFont=false`),
  поэтому, как и предсказывала П3, GoLabel рисует штрихкод сам и шлёт `Q`. Все 9 штрихкодов

  `gkv-avto-box` → `*4111260024*`.
- **Графика и логотипы — `Q` без сжатия**: `Q<x>,<y>,<байт в строке>,<высота>` + `LF`, затем
  растр по 1 биту, `1` = чёрная точка, после растра `CR LF`. Всего 74 картинки, `QA` (zlib) нет.
  `Image` с `LoadToDevice=false` — каждый раз растром, в память принтера не кладётся.
  `Ellipse` — тоже картинкой.
- **Счётчик подставляет GoLabel**: значение `-S0` уходит готовой строкой (`№4021110124183`) или

- **Дата — по-разному.** У `Text` с `UsePrinterClock=true` в байтах остаётся `^D`, а перед
  объектом — формат `Dy2`/`Dy4` (`ATA,…,апр., ^D г.`): дату подставит принтер, байты от даты ПК
  не зависят. В штрихкодах-картинках дату рисует GoLabel по часам ПК: в `gkv-avto-*` (`4111^D%y^C00`)
  и `gkv3-box` (`40211101^D+Y0000^C00`) в растре стоит `26` (2026). **Эти 5 эталонов изменятся со
  сменой года** — тесту порта нужно задавать дату; зависит ли код ещё от месяца — не проверено.
- **Размеры.** `^W` — ширина, `^Q` — длина и зазор, мм, из `Setup` шаблона. «102х152» в имени
  `ГКВ-3 ВМ Наклейка на коробку (102х152)` **не совпадает** с шаблоном: в нём и в байтах 91.5×39
  (`^Q39,9.583`, `^W91.5`), как у остальных коробочных 91.5×39. Наклеек 102×152 среди присланных нет.
  Шаблоны 45.5×19 и 26×17 печатают две наклейки в ряд (`HorAcross=2`).
- **Превью `preview.bmp` на деле PNG** (сигнатура `89 50 4E 47`), хотя расширение `.bmp`.

### Новые грабли съёма

- **Шаблон «только для чтения» вешает GoLabel.** `Copy-Item` сохраняет атрибут, GoLabel после
  печати не может перезаписать копию и показывает окно «Unable to save customer object! Access to
  the path … is denied» — до таймаута. Байты при этом уже отправлены. `capture.ps1` теперь
  снимает «только чтение» с копий.
- **`-db` не отключает MySQL-источник шаблона** (живой прогон, см. выше). Без `-db` такой
  шаблон тоже идёт в базу из `.ezpx` — со стенда это 192.168.88.238:3306 с логином человека;
  один раз так и случилось при повторном съёме, байты с данными удалены, не сохранялись.
  `capture.ps1` теперь передаёт `-db` и в превью, но для MySQL-шаблонов это не спасает.
- **В `.ezpx` есть `&#x0;`** (`<Description>&#x0;…`) — обычный `XDocument.Load` падает с
  `XmlException`. Читать с `XmlReaderSettings { CheckCharacters = false }` (так исправлен
  `GoldenFolderTests`; порту П5 — так же).

## Осталось

7. Карточка П2 → «готово», когда будет эталон 14-го шаблона (или пользователь скажет его не
   снимать) и сверка печати из окна (ниже).

### Печать из окна GoLabel — когда понадобится

Все эталоны снимаются командной строкой, а люди печатают из окна. В окне путь другой
(`SvgArtiste` → `GlobalPrint`): может добавиться `~D…` (синхронизация часов, если включена),
подсказки вводятся руками, настройки печати берутся из окна. Чтобы порт (П5) совпадал с тем,
что реально уходит с рабочего места, нужна **одна сверка**: тот же шаблон, напечатанный из окна
на `127.0.0.1:9101`, против эталона командной строки. Понадобится **на шаге 6**, после первых
настоящих эталонов. Делает пользователь (временно сменить принтер в окне и вернуть
192.168.55.127); фейк поднимает `GGA1C.Sync.FakePrinter --port 9101 --out <папка>`.

## Что нужно от пользователя

- **`ГКВ-3 коробка переменная из гга1с.ezpx`** — для эталона нужна копия шаблона, привязанная
  не к MySQL, а к CSV («Подключить базу» → CSV в GoLabel), плюс 1–3 строки данных в том же
  порядке колонок, что `my_labels`: `date, product_code, mode_code, article, name, manufacturer,
  barcode, qty, extra1, extra2, extra3, external_id, updated_at` (шаблон печатает `^F00` = `date`
  и `^F01` = `product_code`), например
  `2026-10-28,4021110124080,M1,ART-1,TEST,TEST,4021110124080,1,,,,golden-1,2026-10-28 12:00:00`.
  Либо сказать, что шаблон ещё в работе и снимать его рано.
- Сверка печатью из окна (см. выше) — один шаблон, например `gkv1-vm-box`.
- Есть ли шрифт `A` (`GlavkonGOST Type A`) в памяти 192.168.55.127 — подтвердить пользователю
  (тестовая печать из окна; сами принтер не трогаем).
