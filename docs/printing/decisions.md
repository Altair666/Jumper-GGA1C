# Модуль печати — решения

Принято 2026-10-28. Не переоткрывать без новой причины.

## Сценарий

1. Человек в виджете Grist выбирает **базовую платформу** (`Basic_platforms`) — виджет
   показывает шаблоны из хаба для неё. Выбирает **исполнение** (`Modifications`, на этикетке
   поле «Конфигурация» = `mode_code`) — добавляются шаблоны исполнения.
2. На платформу и на исполнение можно прикрепить **несколько шаблонов**; нужный выбирают из
   меню. Сначала платформа, потом исполнение.
3. Шаблона нет или его надо поправить — «Создать / редактировать шаблон» открывает страницу хаба
   с подставленными платформой и исполнением. **Сначала отдельной страницей**, встраивание в
   виджет — отдельная задача позже.
4. Печать:
   - **PDF-этикетки** — как сейчас, через PDF;
   - **наклейки на изделие и на коробку** (`.ezpx`) — кнопка в виджете → команда хабу → хаб по
     сохранённым настройкам шаблона отправляет задание на принтер **от имени нажавшего** и
     пишет в журнал.
5. **Права на все принтеры одинаковые**: кто может печатать на одном, может и на другом.

## Данные

- **Дерево изделий ведёт Grist** (`Basic_platforms`, `Parts`, `Modifications`, `Orders`,
  связаны через `Products`). Хаб хранит только шаблоны и id из Grist — переименование изделия в
  Grist ничего не ломает.
- Шаблоны сейчас лежат в Grist (`Report_template`: `Name`, `GroupCount`, `Fields`, `PdfBase64`,
  `BasicPlatform`, `UpdatedAt`, `UpdatedBy`) и привязаны только к платформе. Колонка
  `BasicPlatform` на стенде имеет тип `Ref:Report_template`, но хранит id `Basic_platforms` —
  виджет берёт сырой id. Два PDF по ~15,6 МБ: лимит JSON-тела Grist — 1 МБ.
- **Переносчик шаблонов не нужен**: на стенде старые шаблоны можно оставить или почистить, на
  боевой машине пользователь переносит сам через создание шаблона в хабе.
- Пример верной привязки: «Этикетка ГКВ-3» и «ГКВ-3 ВМ» висят на «ГКВ-1-OEM (v3)» — это их ядро.

## Вход

Страница шаблонов должна знать, кто пришёл, поэтому **вход в хаб через Keycloak** — часть
модуля печати (сделано в П7: `docs/platform/p7-keycloak-login.md`).

**Встраивание в виджет** (позже): хаб должен разрешить показ в фрейме для адреса Grist, а вход
внутри фрейма — **только по токену**, который виджет передаёт сообщением: кука хаба внутри
чужого сайта считается сторонней, браузеры её режут. На стенде Grist и хаб на одном IP — там
сработает и кука, в бою (db.mp-lab.ru) — нет. Это та же природа, что у бага П1.

## Принтеры

- **GoDEX ZX430i** (EZPL) — сейчас; **CAB EOS1** (JScript) — потом, по бесплатному руководству
  CAB по программированию (cablabel S3 Lite бесплатная, отдельного SDK не найдено).
- Подключение **по Ethernet**, TCP 9100: хаб шлёт задание напрямую, посредник на рабочих местах
  не нужен. Сервер хаба должен видеть сегмент принтеров.
- **Справочник принтеров**: имя, IP, модель → протокол, размер носителя, **загруженные шрифты**.
- Библиотека протоколов с интерфейсом драйвера — CAB добавляется без правки остального.

## Шрифты

Русские шрифты **загружаются в память принтера один раз** при создании шаблона (сейчас через
GoLabel); печать потом ссылается на шрифт по имени — хаб шлёт текст командой EZPL, не картинкой.
На настоящем ZX430i шрифт уже загружен (профиль TA, в эталонах — шрифт `A`, GlavkonGOST Type A).

**Загрузка шрифта в принтер должна быть и в веб-версии** — как в GoLabel (решение пользователя
2026-10-28). В GoLabel её делает нативная `FontFile.dll` (готовит файл шрифта из шрифта Windows,
в т.ч. для EPL), сама загрузка уходит командами EZPL. Как переносить — разобрать отдельной
задачей (П15): по командам, которые GoLabel шлёт при загрузке шрифта на фейк-принтер.
Хаб знает, какие шрифты в каком принтере, — редактор не даёт выбрать шрифт, которого в принтере нет.

## Источник логики — GoLabel II

`C:\Program Files (x86)\GoDEX\GoLabel II`, версия `GoLabel.exe` 2.1. Решение пользователя:
**портировать, а не писать заново** — заново значит собирать баги, которые GoLabel уже вылечил.

|---|---|---|
| `QLabelSDK.dll` 1.5 | .NET Framework 4.6.2, без обфускации; модель, `.ezpx`, сборка команд EZPL (в нём `^Q`, `^W`, `^L`, `^H`, `^XSET`) | **Декомпилировать и портировать на .NET 10** |

не найдено. Решение принято пользователем для внутреннего использования.

## Проверка порта

**Фейк-принтер** — слушатель TCP (для эталонов порт 9101, чтобы не путать с настоящим 9100), пишет
всё пришедшее в файл. На него печатают GoLabel из командной строки и наш порт. **Шаблоны и эталоны в репозиторий не кладём** (решение пользователя) —
они лежат в `C:\GGA1C\golden\<имя>\`; тесты берут путь из переменной окружения и пропускаются, если
эталонов нет. Эталонные тесты требуют **побайтового совпадения**
(«тот же `.ezpx` → те же байты»). Заодно видно, загружает ли GoLabel шрифт и в какой кодировке
идёт русский текст.

## Редакторы

- **PDF** — переносится из виджета в хаб.
- **Наклейки** — веб-редактор: функции GoLabel + редизайн + часть функций Graphite. Перед
  реализацией — отдельное обсуждение и дизайн.

## Баг, который делаем первым

При синхронизации из виджета всплывает окно входа Keycloak. Виджет держит токены только в
памяти; когда тихий вход во фрейме (`prompt=none`) не удаётся, открывается окно
(`_kcSilentLogin` → `_kcPopupLogin`, `index.html` виджета ~2672). Гипотезы: сессия Keycloak
истекает раньше сессии Grist (по умолчанию 30 минут простоя); браузер не отдаёт куку Keycloak
во фрейм. Сначала найти причину, потом чинить — правка может оказаться в настройках реалма, а не
в коде. Пользователь прямо просил обходиться без этого окна.
