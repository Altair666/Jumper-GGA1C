# ZX430i: настройки в редакторе

- Модель — элемент `PrinterModel` в EZPX. Выбрать модель можно только если элемент пуст/отсутствует.
  Для не-ZX430i настройки не реализованы; геометрия, DPI и координаты шаблона не пересчитываются.
- «ОК» сохраняет изменения страницы без правок объектов, а без изменений не создаёт версию.
  Сравнивается хэш открытого файла. Существующие значения вне списка и отсутствующие атрибуты
  сохраняются как есть, пока соответствующее поле не изменено.
- Профиль — `Printing:ProfilesFolder/<tenant>/zx430i.json` (по умолчанию `C:/GGA1C/printer-profiles`).
  `SchemaVersion: 1`, `Connection` хранит `Type`, `IPv4`, `Port` и один раз принятое решение об импорте.
  JSON старого формата читается без миграции MySQL и обновляется при следующей правке. Опции
  приложения хранятся отдельно в `application.json` той же организации.
- Для LAN EZPX использует элементы `CommunicationType=Network`, `NetworkIPAddress` (первый октет
  в младшем байте), `NetworkPort`. Пока в профиле нет IPv4, запись эти элементы не изменяет,
  в том числе не создаёт отсутствующие. Адрес из файла не используется для обращения к принтеру.
- Длина в профиле — неотрицательное число в мм без верхней границы. После подтверждения поле,
  полоса и линейка обновляются по событию профиля в открытых редакторах хаба. Прочитанное из
  принтера значение показывается отдельно и применяется только через «Принять в профиль».
  При записи диапазон проверяется до округления: 0–3 мм, округление до целых мм от половины вверх,
  затем команда получает десятые доли мм. Изменение единицы округляет только отображение.

## Протокол и режим записи

`Printing:SettingsDryRun` (переменная `Printing__SettingsDryRun`) по умолчанию `true`. «Задать» и
`Buzzer` в этом режиме даже не открывают TCP-соединение: показывают и журналируют команды.
«Обновление» допускает строго формы без параметров из `PrinterSetup.cs:5874–5890`:
`^XSET,NETCONFIG`, `^XGET,LANGUAGE`, `^XGET,KEYBOARD`, `~S,OFFSETX`, `~S,OFFSETY`, `^XSET,DISMOFFSET`.
Не отправляются ни гипотетические запросы, ни значения из шаблона. Команды с параметрами — запись.
Ответ читается обычным TCP с CRLF до полной строки `Unprintable` либо таймаута; неизвестные и
отсутствующие поля не заполняются значениями по умолчанию. Транспорт пробной печати не используется.

«Сканировать» проверяет черновые IPv4 и порт. Один UDP-запрос `Where is Godex Printer?` на 8888
отправляется по непосредственно подключённой подсети хаба (/24–/30); для более широкой сети,
loopback или /31–/32 — только на указанный адрес. Приём на 6666, две секунды, поиск можно
отменить. Только структурированный ответ с моделью ZX430i и совпадающим IPv4 источника
считается находкой (`ConnectedPrinter.cs:181–205`, `UDP_Server.cs:147–235`). Не проверяются
TCP-порты, и результат не пишется в профиль без выбора и сохранения.

Порядок и подписи списков взяты из `PrinterSetup.cs:8640–8845`, ветка ZX430i исключает две
строки языков (`:5836–5844`), подписи — `QlabelDlg.PrinterSetup.ru-RU.resources`. Список
скорости и яркости — `PrinterModel.xml:3200–3206`. Запись параметров — `PrinterSetup.cs:6051–6104`.
Зуммер — `ConnectedPrinter.cs:494–513`: `^XGET,APPINFO2`, три `^XSET,BUZZER,1` по 200 мс,
условное восстановление `^XSET,BUZZER,0` только при подтверждённом выключенном состоянии.
