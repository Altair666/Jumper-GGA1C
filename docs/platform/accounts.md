# Учётки людей и опознание

## Как это устроено сейчас

Сущность **`LabelClient`** (`Domain/Labels`) — по факту учётка человека, хотя название
осталось от печати: имя, `Slug` (имя папки буфера), `KeyHash`/`KeyPrefix`/`KeyEncrypted`
(запасной ключ), `IsEnabled`, `LastUsedAt`, связь с Keycloak (`KeycloakSub`,
`KeycloakUsername`, `Email`, `SyncDisabledAt`, `SyncedAt`), учётные данные Altium и PDM,
`PrintLogin`. В модуле печати её предстоит превратить в общую учётку человека с привязанными
учётками других систем.

## Учётки приходят из Keycloak

Люди не заводятся руками: хаб забирает их из Keycloak служебной учётной записью клиента
(`grant_type=client_credentials`). Клиенту нужны включённая служебная учётка **и роль
`view-users` из `realm-management`** — без роли токен выдаётся, а список пользователей отвечает
403. `KeycloakClient.Hint()` переводит типовые отказы в подсказки. На стенде — клиент
`gga1c-sync`, секрет в `/opt/grist/gga1c-sync-secret.txt`.

**Настройки** `Sync.Keycloak.*` задаются переменными окружения при первом запуске
(`Keycloak__BaseUrl`, `Keycloak__Realm`, `Keycloak__ClientId`, `Keycloak__ClientSecret`) и
переносятся в хранилище засевом `KeycloakSettingsDataSeedContributor`; секрет шифруется. Уже
заданные значения не перезатираются — правка через UI не отменяется миграциями.

**Страница `/keycloak`** — подключение, проверка связи, синхронизация и короткая таблица «что
здесь что» (реалм, клиент, секрет) — эти три вещи спрашивают каждый раз.

**Связь по `sub`**, не по email или логину — их человек меняет. Учётка, заведённая руками,
один раз привязывается по email, чтобы не получить вторую на того же человека.

**Имя папки буфера** — транслитерация фамилии (`SlugGenerator`), при совпадении добавляется
число. При смене фамилии папка не переименовывается — путь уже прописан на рабочих местах.

**Кто отключил учётку.** Обратно включаются только учётки с `SyncDisabledAt`, то есть
отключённые самой сверкой. Иначе следующая сверка вернула бы доступ тому, кого администратор
выключил руками. Проверено на стенде.

**Периодическая сверка** — `KeycloakSyncWorker`: первый тик через минуту после старта, дальше
раз в час. Это требование, а не удобство: без сверки уволенный продолжал бы печатать.

**Удаление учётки** убирает логин печати в MySQL и её строки из `AppLabels`.

## Вход в сам хаб

Сотрудник входит кнопкой «Keycloak» (клиент `gga1c-hub`). Пользователь хаба связан с учёткой
тем же `sub` (запись `AbpUserLogins`); нет учётки — заводится при входе, по почте или логину
к чужим учёткам не привязывается. Выключили учётку (сверкой или руками) — пользователь хаба
становится неактивным, открытая сессия гаснет в пределах 2 минут. Админку видит только роль с
правом `Sync.Admin`. Подробности — `docs/platform/p7-keycloak-login.md`.

## Учётные данные во внешних системах

В карточке учётки (кнопка с человечком) — логин и пароль **Altium** и **SOLIDWORKS PDM**:
`AltiumLogin`, `AltiumPasswordEncrypted`, `PdmLogin`, `PdmPasswordEncrypted`,
`CredentialsUpdatedAt`. Пароли шифруются в `LabelClientStore.SetCredentialsAsync` и наружу не
отдаются — в поле приходит маска длины (`SecretMask`): одни точки — не менять, пусто — удалить,
иное — новое значение (см. `docs/platform/environment.md`).

Пароль PDM хранится вынужденно: **PDM не умеет ни SAML, ни OIDC**, а действовать от имени
человека без его пароля нельзя (`LoginAuto` входит тем, кто уже вошёл на машине, `Login`
требует пароль, подмены пользователя нет). Расшифровка пока нигде не вызывается.

## Опознание человека в запросе от виджета

**Решено: токен Keycloak.** Виджет входит в Keycloak (публичный клиент `gga1c-widget`, PKCE
S256, тихий вход во фрейме, при неудаче — всплывающее окно) и шлёт токен; хаб проверяет
подпись по JWKS, издателя, срок и клиента (`KeycloakTokenVerifier`) и пишет строки с меткой
человека. Grist в опознании не участвует.

Почему не иначе: в plugin API Grist нет `getUser`; сессионная кука `grist_core` —
`HttpOnly; SameSite=Lax`, из JS не читается и кросс-сайтом не уходит; кука ставится без
`Domain` (host-only), поддомен вида `sync.mp-lab.ru` её не получит — только тот же хост по
другому пути. Отвергнутые варианты — в `docs/summary.md` §7.

Если снова встанет вопрос чтения из Grist по правилам доступа: эндпоинт `/sql` для этого **не
годится** — требует `canCopyEverything` и ограниченному пользователю отдаёт 403, а не
отфильтрованные строки. Работает `fetchTable` из виджета.

**Известный баг:** когда тихий вход не удаётся, при синхронизации всплывает окно входа
Keycloak. Это задача П1 в `docs/roadmap.md`.

**Запасной ключ учётки** (`X-Api-Key` / `Bearer`) ещё принимается — убрать, когда все виджеты
переведены на токены.

## Журнал

Модуль аудита ABP подключён (`AbpAuditLogging`), запросы пишутся в базу. Страницы журнала нет
(UI аудита в ABP коммерческий), и запросы виджета опознаются своей проверкой токена, а не
механизмом ABP — автор в журнале у них, вероятно, пустой. Это задача модуля печати.

Отдельно есть журнал входящих запросов (`Diagnostics/RequestLogStore`).
