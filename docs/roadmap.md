### БАГ-1. GoLabel не входит в MySQL после перезапуска MySQL
**Статус:** работает на стенде с 2026-10-28 20:58 (в журнале хаба «Пароли логинов печати в кэше
MySQL: 7 из 7»). Решение пользователя —
вариант (а), минимум: `PrintLoginCacheWarmer` при старте хаба входит каждым включённым логином
печати по TLS; `EnsureAsync` после `ALTER USER` делает то же для своего логина. Перезапуск
MySQL при работающем хабе сбрасывал кэш до перезапуска хаба — решается в БАГ-1.1 (тик работника).
**Причина (проверено):** GoLabel жёстко задаёт `SslMode=none` и не разрешает получение RSA-ключа
(`QLabel.cs:7144`, `dbProperty.cs:44` в `C:\GGA1C\golabel-src`). Полную проверку
`caching_sha2_password` без TLS/RSA он не проходит — входит, только пока у сервера есть кэш
пароля. Кэш чистит перезапуск MySQL (был 25.10), `FLUSH PRIVILEGES`, `ALTER USER`. Ошибка:
`authentication method "caching_sha2_password" failed ... allowpublickeyretrieval=true`.
**Заплатка:** по разу вошёл каждым логином печати по TLS (`mysql --ssl-mode=REQUIRED`) — кэш
заполнен, вход без TLS проходит. Слетит при следующем перезапуске MySQL.
**Варианты:** (а) хаб сам «прогревает» кэш — `PrintConnectionWorker` раз в N минут входит
каждым логином печати по TLS (пароли у хаба есть); глобальные настройки MySQL не трогаем;
(б) логины печати на `mysql_native_password` — в 8.4 плагин выключен, нужно `mysql_native_password=ON`
в `my.ini`, перезапуск MySQL и правка `MySqlPrintLoginService` (в MySQL 9 плагина уже нет).

окно и командная строка дают те же байты (сверено в П2).

описан (для `AT` — вместе со стилем `B/T/U` и кодировкой `E`), а **`P1/P2/P3` в доступной версии
руководства нет** — это расширение новых прошивок. **Вывод (гипотеза, не проверено на ZX430i):**
блок 5 «не по центру» — прошивка не понимает `P2` и печатает от `x` как от левого края (текст
сдвинут вправо на полстроки). По повороту байты GoLabel соответствуют руководству; в
напечатанном шаблоне (`тестовая печать.ezpx`, байты — `C:\GGA1C\golden\test-print\sent-one-label.bin`)

`ATt` с `E`. Номер «блок 1» пользователя к этому шаблону не привязан (подписи блоков есть только
в `_2`) — уточнить.

сам считать левый край по ширине строки (как делает превью GoLabel) и не слать `P2/P3`, но байты

### БАГ-1.1. Кэш паролей печати после перезапуска одного MySQL
**Статус:** код готов (2026-10-29); вживую — после перезапуска живого хаба и службы MySQL (основной
агент). **Как сделано:** `PrintConnectionWorker` (тик 2 мин, первый тик — сразу при старте,
`RunOnStart`) читает `SHOW GLOBAL STATUS LIKE 'Uptime'` учёткой приложения (`MySqlServerUptime`;
проверено вручную — `gga1c_app` читает без особых прав). `MySqlRestartDetector.ShouldWarm`: прежнего
замера нет (первый тик после старта хаба) или сервер запущен позже, чем выходит по прежнему замеру
(`Uptime` < прежний `Uptime` + прошедшее время − 5 с; ловит и перезапуск, после которого `Uptime`
успел стать больше прежнего) — `PrintLoginCacheWarmer.WarmAllAsync`. Отдельный `Task.Run` прогрева в
`SyncBlazorModule` убран — при старте греет только первый тик, без дубля. Замер запоминается после
прогрева: недоступный MySQL — следующий тик пробует снова. Второй экземпляр с
`Workers__Enabled=false` не греет (как и раньше). Тест — `MySqlRestartDetectorTests` (6 случаев).
**В журнале:** при старте — «Первый тик работника печати: MySQL работает N с…», после перезапуска
MySQL — предупреждение «MySQL перезапущен (Uptime N с, на прошлом тике M с)…», затем «Пароли
логинов печати в кэше MySQL: k из n».
**Цель:** хаб сам замечает перезапуск MySQL (например, `Uptime` меньше прежнего в
`PrintConnectionWorker`) и снова заполняет кэш паролей логинов печати; старт хаба остаётся
частным случаем того же механизма. **Готово, когда:** после перезапуска службы MySQL при работающем
хабе GoLabel входит без ручных действий в течение одного тика работника (не проверено вживую).
